# 1. 온보딩 및 로그인

PRD 1번 "온보딩 및 로그인" 항목에 대응. 앱 미설치/미로그인 상태에서의 첫 진입 흐름.

## 1-1. 온보딩 - 가치 소개

### 화면 목적
앱의 핵심 가치(공동 가계부/일정)를 첫 화면에서 전달.

### 레이아웃
- 중앙: 아이콘/일러스트 자리 + 타이틀("둘이 함께 쓰는 가계부") + 보조 설명("지출과 일정을 한눈에")
- 하단: 페이지 인디케이터(점 2개 중 1번째 강조) + "다음" 버튼

---

## 1-2. 온보딩 - 연결 안내

### 화면 목적
상대방 연결 방식을 미리 안내 (이 시점엔 실제 연결 액션 없음, 설명만).

### 레이아웃
- 중앙: 아이콘(연결 표시) + 타이틀("초대코드나 QR로 상대방과 연결") + 보조 설명("로그인 후 언제든 연결할 수 있어요")
- 하단: 페이지 인디케이터(점 2개 중 2번째 강조) + "시작하기" 버튼 → 로그인 화면으로 이동

---

## 1-3. 로그인

### 화면 목적
구글 로그인으로 서비스 진입. (카카오 로그인은 추후 적용 예정 — PRD 1번 참고)

### 레이아웃
- 중앙: 앱 로고 자리 + 앱 이름("같이살림") + 슬로건("함께 보는 우리 가계부")
- 하단: "Google로 계속하기" 버튼(구글 로그인 가이드라인 준수) + 약관 동의 안내 문구(작은 글씨)

### 상태 분기 (확정)

구글 로그인은 Credential Manager로 띄운다. (레거시 GoogleSignIn API는 deprecated)

| 상황 | 처리 |
|---|---|
| 사용자가 시트를 닫음 (취소) | **안내 없음.** 로딩만 풀고 로그인 화면 유지 — 스스로 닫은 행동에 에러를 띄우지 않는다 |
| 기기에 구글 계정 없음 | "기기에 로그인된 구글 계정이 없어요. 계정을 추가한 뒤 다시 시도해주세요." |
| 그 외 실패 (네트워크/토큰 등) | "로그인에 실패했어요. 잠시 후 다시 시도해주세요." + 버튼 재시도 가능 |
| 로그인 진행 중 | 버튼 자리에 스피너, 버튼 비활성 |

- **최초 로그인 vs 재로그인은 UI를 분기하지 않는다.** Firebase Auth가 같은 흐름으로 처리하고,
  `users/{uid}` 문서 upsert가 두 경우를 흡수한다 (최초에만 `createdAt`/`providers` 생성, 재로그인은 `lastLoginAt` 갱신).
- 로그인 성공 시 이 화면이 직접 홈으로 이동하지 않는다 — 인증 게이트가 Firebase auth 상태를 관찰해 이동시킨다.

### 추후 확정 필요
- 동일 이메일의 다른 로그인 방식 연동 시 계정 연결(linking) UX (카카오/애플 추가 시 논의)
- 약관/개인정보처리방침 실제 링크 연결 (현재는 문구만 노출)
