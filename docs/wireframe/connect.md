# 9. 상대방 연결

PRD 9번 "상대방 연결"에 대응. 로그인 후 두 사람을 하나의 공동 데이터 공간으로 묶는 흐름.

연결 해제/회원탈퇴는 30일 유예 삭제에 서버 작업이 필요해 1차 범위 밖이다 (PRD 9 "1차 구현 범위"). 이 문서는 **연결하기**만 다룬다.

## 진입점
- 홈 상단 "상대방을 연결해보세요" 배너 (미연결 시 상시 노출 — home.md 1-1)
- 설정 최상단 연결 상태 카드 (settings.md 2)

둘 다 9-1로 간다.

---

## 9-1. 연결 관리

### 화면 목적
연결 상태를 보여주고, 미연결이면 두 갈래(코드 만들기 / 코드 입력하기) 중 하나로 보낸다.

### 레이아웃 — 미연결
1. **상단** — 뒤로가기 + 타이틀("상대방 연결")
2. **안내 영역** — 아이콘(연결 표시) + "함께 기록할 상대방과 연결해보세요" + 보조 설명("연결 전에 각자 쓴 기록은 그대로 본인만 볼 수 있어요")
3. **주 액션** — "초대 코드 만들기" (하단 고정 CTA와 동일 스타일, 화면 폭 100%) → 9-2
4. **보조 액션** — "받은 코드 입력하기" (테두리 없는 텍스트 버튼) → 9-3

> 주/보조를 나누는 기준: 먼저 연 사람이 코드를 만드는 쪽이 자연스럽다. 둘을 같은 무게로 두면 매번 어느 쪽인지 판단해야 한다.

### 레이아웃 — 연결됨
1. **상단** — 뒤로가기 + 타이틀("상대방 연결")
2. **연결 카드** — 프로필 아이콘 2개 겹침 + "○○님과 연결됨" + "2026.03.14부터 함께 기록 중"
3. **연결 해제** — 경고색 텍스트. **1차에서는 비활성**("준비 중")으로 노출한다

---

## 9-2. 내 초대 코드

### 화면 목적
코드와 QR을 상대에게 전달하고, 상대가 수락하는 순간을 기다린다.

### 레이아웃 (위→아래 순서)
1. **상단** — 닫기(X) + 타이틀("초대 코드")
2. **코드 표시** — 6자리를 큰 글자로. 헤드라인 서체(Gowun Batang), 글자 간격을 넉넉히 벌려 한 글자씩 읽히게 한다. 탭하면 클립보드 복사 + "복사했어요" 토스트
3. **QR 카드** — 흰 카드 위 QR. **QR 아래에 코드 원문을 병기**한다 (스캔이 안 될 때 손입력으로 넘어갈 수 있도록)
4. **유효 시간** — "29분 남음" (분 단위 갱신, 1분 미만은 "곧 만료돼요"). 초 단위로 깜빡이게 하지 않는다 — 재촉하는 인상만 남는다. 만료되면 코드/QR 자리를 "코드가 만료됐어요"로 바꾸고 아래 버튼을 "코드 새로 만들기"로 교체
5. **공유하기** — 시스템 공유 시트 호출. 공유 문구에 코드·딥링크와 함께 **유효시간을 명시**한다 (예: "30분 안에 입력해주세요")
6. **코드 새로 만들기** — 텍스트 버튼. 누르면 이전 코드는 즉시 무효

> 유효기간이 30분이라 **만료는 예외가 아니라 흔한 상태다.** 만료 화면에서 새 코드까지 한 번의 탭으로 닿게 하고, 이미 공유한 코드가 죽었다는 사실이 분명히 보이게 한다 (같은 자리에 다른 코드가 조용히 들어차면 상대와 서로 다른 코드를 보게 된다).

### 성사 감지
- 이 화면은 커플 문서를 **실시간 구독**한다. 상대가 코드를 수락하면 별도 조작 없이 9-5로 넘어간다
- 앱을 닫아 둔 사이에 성사됐다면 다음 실행 시 이미 연결된 상태로 진입한다 (홈 배너가 사라지는 것으로 인지)
- 푸시 알림은 1차 범위 밖 (PRD 9 "1차 구현 범위")

### 상태 분기
| 상황 | 처리 |
|---|---|
| 코드 발급 중 | 코드 자리에 스켈레톤, 공유 버튼 비활성 |
| 발급 실패 (네트워크) | "코드를 만들지 못했어요" + 다시 시도 버튼 |
| 유효 코드가 이미 있음 | 새로 만들지 않고 기존 코드를 그대로 보여준다 |
| 만료 | 코드/QR을 안내 문구로 대체 + "코드 새로 만들기" |

## 9-3. 코드 입력

### 화면 목적
상대에게 받은 코드를 넣거나 QR로 스캔한다.

### 레이아웃 (위→아래 순서)
1. **상단** — 닫기(X) + 타이틀("코드 입력")
2. **안내 문구** — "상대방이 공유한 6자리 코드를 입력해주세요"
3. **코드 입력 필드** — 6칸 분할 입력. 자동 대문자 변환, 한 글자 입력 시 다음 칸으로 포커스 이동, 지울 때 이전 칸으로 복귀. 붙여넣기하면 6칸에 나눠 채운다
4. **오류 문구 자리** — 입력 필드 바로 아래. 비어 있어도 자리를 유지해 문구가 뜰 때 레이아웃이 밀리지 않게 한다
5. **QR로 스캔하기** — 텍스트 버튼. 시스템 스캐너를 띄우고, 인식되면 코드를 6칸에 자동으로 채운다
6. **하단 고정 CTA** — "연결하기". 6자리가 다 차기 전에는 비활성. 누르면 코드를 조회해 발급자를 확인한 뒤 9-4 확인 시트를 띄운다 (조회 실패 시 시트 없이 4번 자리에 오류 문구)

### 딥링크 진입
`salim://invite/{코드}`로 들어오면 이 화면을 코드가 채워진 상태로 연다. 코드가 6자리 형식에 맞지 않으면 빈 화면 + "코드 형식이 올바르지 않아요".

---

## 9-4. 확인 시트

### 화면 목적
연결은 되돌리기 어려운 동작이라, 상대가 맞는지와 기존 기록이 어떻게 되는지를 한 번 확인시킨다.

### 레이아웃 (하단 바텀시트)
1. **타이틀** — "○○님과 연결할까요?"
2. **안내 문구** — "지금까지 각자 쓴 기록은 그대로 본인만 볼 수 있어요. 연결한 뒤에 쓴 기록부터 함께 보여요."
3. **버튼 2개** — "연결하기"(주) / "취소"(보조)

연결 진행 중에는 버튼 자리에 스피너, 시트는 닫히지 않는다.

---

## 9-5. 연결 완료

### 화면 목적
성사를 확실히 알리고 홈으로 돌려보낸다. 발급자(9-2)와 수락자(9-4) 양쪽이 이 화면에 도착한다.

### 레이아웃
- 중앙: 프로필 아이콘 2개 겹침 + "○○님과 연결됐어요" + 보조 설명("이제 가계부와 일정을 함께 봐요")
- 하단: "홈으로" 버튼 — 백스택을 비우고 홈으로 (연결 흐름 화면들이 뒤로가기에 남지 않게)

---

## 상태 분기 종합 (확정)

각 실패를 **어디서 잡는지**가 중요하다. 서버가 없어 클라이언트 검증이 UX용이고 최종 방어선은 보안 규칙이라, 두 층이 각각 무엇을 막는지 구분해 둔다.

| 상황 | 잡는 곳 | 문구 | 복구 동선 |
|---|---|---|---|
| 없는 코드 / 오타 | 클라이언트 (초대 문서 조회 실패) | "코드를 다시 확인해주세요" | 입력값 유지, 재입력 |
| 만료된 코드 | 클라이언트 (`expiresAt` 비교) | "코드가 만료됐어요. 상대방에게 새 코드를 요청해주세요" | 입력 초기화 |
| 본인이 발급한 코드 | 클라이언트 + 규칙 | "내가 만든 코드예요" | 9-1로 |
| 내가 이미 연결됨 | 클라이언트 (내 연결 상태) | "이미 연결된 상태예요" | 9-1로 |
| **상대가 이미 다른 사람과 연결됨** | **보안 규칙만** | "상대방이 이미 다른 분과 연결돼 있어요" | 입력 초기화 |
| QR 형식 오류 | 클라이언트 | "QR을 다시 확인해주세요" | 다시 스캔 |
| 네트워크 오류 | 클라이언트 | "연결에 실패했어요. 잠시 후 다시 시도해주세요" | 재시도 |

> **"상대가 이미 연결됨"이 유일하게 규칙에만 걸린다.** 상대의 `users` 문서는 본인만 읽을 수 있어 클라이언트가 미리 확인할 방법이 없다. 쓰기가 `PERMISSION_DENIED`로 거절되는 것으로만 알 수 있으므로, 이 오류 코드를 위 문구로 번역해야 한다. 다른 거절 사유(만료 코드로 시도 등)도 같은 오류 코드로 오기 때문에, 클라이언트가 사전 검증에서 이미 걸러낸 뒤 남은 `PERMISSION_DENIED`를 이 문구로 본다.

## 미확정 사항
- 연결 완료 후 상대의 생일/기념일을 디데이에 함께 띄울지 (firestore-schema.md 미확정 사항 참고 — PRD 6과 직결)
- 연결 해제 화면 (다음 단계). 해제 후 유예기간 중 공동 데이터를 어디서 열람하는지도 그때 함께 정한다
- 공유 문구 최종안 (앱 미설치자가 받았을 때 무엇을 보게 되는지 포함)
